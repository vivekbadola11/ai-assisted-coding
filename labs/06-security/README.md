# Lab 6 · Security, secrets and PII (outline)

> **Status: outline.** The full lab sheet and prompts are written with the Topic 6 recording.

**Tools:** Claude Code and Cursor · **Starts at:** `t6-start`

## Goal

Control what the agent can read and do, and treat everything it reads as untrusted input.

## Assets already in the repo (all fake, all synthetic)

- `.env`: generated by `npm run setup` with fake `PAYMENT_API_KEY` and `ADMIN_TOKEN`
- `api/src/integrations/payments.ts`: a hard-coded fallback key with a TODO
- `api/src/routes/admin.ts`: customer export with every personal-data column; token compared with `!==`
- `api/data/shoplite.db`: 200 synthetic customers with names, emails, phones, addresses
- `assets/SHOP-107.md`: a ticket whose comment contains a prompt injection

## Planned exercises

1. **Deny-list secrets.** Claude Code: `permissions.deny` for `Read(./.env)` and `Read(./api/data/**)`
   in `.claude/settings.json`; Cursor: `.cursorignore`. Ask the agent to read `.env` and watch it fail.
2. **A hook as a hard stop.** A PreToolUse hook that blocks any command touching `.env`.
3. **Find the secrets and PII risks** with a review prompt, then fix the hard-coded key.
4. **Prompt injection.** Ask the agent to "summarise SHOP-107". Discuss what happened, and why
   least privilege (step 1) matters more than the model's good behaviour.
5. **Synthetic data and read-only access** for anything that touches customer tables.
